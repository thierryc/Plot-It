Self-host Plot-it.

Run the app and its plotter server on your computer or Raspberry Pi. The API serves the interface; an independent runner owns the EBB and executes accepted drawings.

This release is for a trusted LAN. It has no login. Origin and Host checks are not authentication. Public tunnels and public server exposure require authentication in a future release.

Desktop setup

Install Git and NVM using its official instructions. The supported runtime is Node 24.21.0 LTS, pinned in .nvmrc. The shell wrappers below target macOS/Linux or a compatible Unix shell; native Windows server installation has not been qualified.

git clone https://github.com/thierryc/Plot-It.git
cd Plot-It
scripts/node-lts.sh --npm ci
scripts/node-lts.sh --npm test
scripts/node-lts.sh --npm run build

The wrapper installs the pinned Node through NVM only when missing, verifies its LTS designation and executable path, and launches that executable directly. A successful nvm use alone can leave a conflicting executable earlier on PATH. Services never upgrade their runtime at startup.

Start the two processes in separate terminals:

scripts/node-lts.sh --npm run server:runner
scripts/node-lts.sh --npm run server:api

Open http://127.0.0.1:8787 on that computer. Choose Network plotter → Take control → Connect EBB. The default manual policy leaves USB available when the server starts.

Raspberry Pi installation

The reference target is Pi 4 with Raspberry Pi OS Lite 64-bit; hardware acceptance is pending. Pi 3 and Zero 2 W remain unvalidated. The installer does not support ARMv6/ARMv7 or obsolete Node runtimes.

Build and package on your development computer:

scripts/node-lts.sh --npm run build
deploy/package-release.sh

Transfer output/plot-it-pi.tar.gz to the Pi and unpack it. Use a directly attached terminal or your preferred transfer method; ongoing browser operation does not require SSH. This guide describes the existing packaging workflow, not a published binary download.

On the Pi, install prerequisites, then run the installer from the unpacked directory:

sudo apt update
sudo apt install ca-certificates curl build-essential python3
sudo deploy/install-pi.sh

The installer creates a dedicated plot-it account with dialout access, installs under /opt/plot-it, resolves the pinned NVM Node executable, and creates separate plot-it-api and plot-it-runner systemd units. It enables services without starting hardware or overwriting existing configuration.

Production dependencies are installed for the Pi’s architecture. Never copy macOS node_modules onto it. Compiler/Python prerequisites support building native bindings if an ARM64 prebuilt binding is unavailable.

Set the device in /etc/plot-it/environment using its real /dev/serial/by-id/ path. A blank EBB_DEVICE selects a device only when exactly one matching EBB is detected. USB CDC does not require the GPIO UART.

The dedicated-Pi example uses PLOT_CONNECTION_POLICY=auto. Choose manual if you want an explicit browser Connect EBB before opening USB. Auto reconnect never starts or replays a drawing.

HTTPS for LAN browsers

The API listens on loopback HTTP port 8787. For other computers on your LAN, configure its HTTPS/WSS listener on port 8443. The runner remains independent of network services.

On your administrative computer, install mkcert and generate a certificate for your actual Pi hostname and DHCP-reserved address:

mkcert -install
mkcert -cert-file lan.pem -key-file lan-key.pem plot-it.local 192.168.1.50

Copy the server certificate and server key to /etc/plot-it, owned by plot-it:plot-it with permissions 0600. Install only the CA’s public root certificate on client devices. Never distribute the CA private key.

Edit /etc/plot-it/environment, replacing these example addresses and device path:

PLOT_ORIGINS=https://plot-it.local:8443,https://192.168.1.50:8443,http://127.0.0.1:8787,http://localhost:8787
PLOT_TLS_CERT=/etc/plot-it/lan.pem
PLOT_TLS_KEY=/etc/plot-it/lan-key.pem
EBB_DEVICE=/dev/serial/by-id/<actual-EBB-device>

The configuration does not create DNS records. Use working hostname resolution or the configured IP address.

sudo systemctl start plot-it-runner plot-it-api
sudo deploy/diagnose-pi.sh

Open https://plot-it.local:8443. HTTP, assets, API, and WebSocket use the same origin. Cross-origin access remains disabled.

Connect and operate

  • Claim control explicitly. Multiple browsers can view; one browser controls the machine.
  • Connect EBB, establish origin, and verify pen calibration before Start. Keep the drawing within the physical travel area.
  • A complete ordered job is uploaded before execution. Pen changes wait at origin with motors engaged and require explicit Continue.
  • “Pausing” acknowledges the request; “Paused” means the runner reports that state after settling.
  • Release control leaves the connection and accepted job running. “Disconnect EBB · release USB” requires the job to settle, raises the pen, releases motors, and invalidates origin.
  • Direct USB and a local server cannot own the same board simultaneously. Release server USB, then click the browser’s Connect button. A remote Pi does not own USB on another computer.
  • Browser closure or API restart does not cancel an accepted job. Runner restart or USB loss interrupts uncertain execution; recovery must be explicit and never replays motion automatically.

The server normally publishes progress at 5 Hz. Position samples are commanded position, not encoder measurements; interpolated preview position is estimated.

Update an installation

Build and test a new release under the pinned LTS runtime. Wait until the runner is idle, stop both services, and install the new package. Keep the previous release and runtime available until verification passes.

sudo systemctl stop plot-it-api plot-it-runner
sudo deploy/install-pi.sh
sudo systemctl start plot-it-runner plot-it-api
sudo deploy/diagnose-pi.sh

Run the installer from the newly unpacked release. Existing configuration is preserved. Review any release-specific configuration changes before restarting.

Troubleshooting

Could not open EBB
Close the other owner: Saxi, another browser tab, or the Node runner’s USB connection. Verify the cable, device path, and serial permissions.
No network destination
Open the app served by your local installation. The public site intentionally offers only Direct USB and Simulation.
Certificate or WebSocket failure
Check CA trust, certificate hostname/IP, port 8443, and the exact configured Origin. Keep HTTPS and WSS on the same origin.
Pen heights or orientation are wrong
Verify calibration and profile against your machine. The app’s AxiDraw profile is not proof of physical AxiDraw testing. NextDraw’s brushless pen lift is not validated.
Server diagnostics
sudo deploy/diagnose-pi.sh checks runtime, services, and device permissions. Review journalctl -u plot-it-api -u plot-it-runner and the live /api/v1/status endpoint.
